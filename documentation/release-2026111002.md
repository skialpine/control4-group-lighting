# 2026111002 — Startup brightness reports

This prerelease corrects two problems with how Light Group reports its state to
Control4.

- Sends the first observed brightness to the lighting proxy after startup or
  reconnect, even if the proxy already shows the same value. This includes off
  (0%). Repeated reports of the same brightness stay quiet afterward.
- Waits for valid bulb data before reporting startup brightness, so missing data
  is not reported as 0%.
- Retries failed proxy capability and brightness messages when the member lights
  have not changed. The retry reports status; it does not send commands to
  bulbs.

The fixes pass automated tests. We are still checking whether the startup change
resolves Home Assistant's brightness error. It does not update the Zigbee bulb
driver or its individual bulb proxies.

## Updating and checking

Select **Update Channel → Prerelease**, then run **Actions → Update Drivers**.
The driver version should become **2026111002**. Keep the existing Light Group
instances and their selected lights.

After updating, check the Front Porch group in Home Assistant with the bulbs
off, then on. Confirm brightness updates without errors. Also check any Control4
programming attached to brightness events: the initial state report can trigger
that programming when the driver starts.

For a manual update, import `light_group.c4z` through Composer. Do not overwrite
files in Composer's Drivers directory.
